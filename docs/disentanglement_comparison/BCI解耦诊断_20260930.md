## 已确认的配置和结构问题

- task summary/correction 对比损失均为 0；subject 两项各为 0.02。missing=20，permute_sub=5，permute_task=20。权重大小本身不等于梯度大小，但当前缺少显式 task 对比约束。
- subject correction loss 最后 train=1.609297，Val=0.693359，接近 ln5 / ln2 的无法区分水平。
- shared、subject、task encoder 各 1 层，每条分支经过 shared+branch 共 2 层；并非通过 12 层分类 Transformer 训练 corrector。
- `_patch_tokens` 仅提取 CNN token；`_encode_dynamic_tokens` 未加入通道/时间位置编码。缺失原型沿 4 个时间片重复，导致 eval 时同一导联 4 个缺失查询相同、输出相同。16 个验证样本实测 d_sub/d_task/预测的跨时间片最大差均为 0，而目标最大差为 0.457660。这是补全的表达限制，增加同类型层数无法消除它；不等于已经证明它是解耦失败的唯一原因。
- 当前修正输出没有 tanh 或 correction_scale 限幅。旧仓库 rawcontra 日志记录 scale=0.02，但旧实验是 multi_subject_json 协议，不能与此次跨被试划分直接归因比较。旧 taskcontra 的最后验证 task 对比损失约 1.38677，仍接近 ln4。

## 推荐实验顺序（尚未训练）

1. 优先给 corrector 的观测 token 和缺失查询加入匹配的通道/时间位置编码；CNN 重建目标仍保持原定义。保留原始、不限幅的修正输出，先保持原深度。
2. 先做 subject/task 双分支表征学习，显式启用两项 correction 对比损失；正样本分别覆盖同被试不同任务、同任务不同被试，检查数据是否支持。早期减弱重建和交换约束，避免很快退化为原型附近的常量预测。具体权重需要观察梯度和验证结果，不能保证一组常数必然成功。
3. 解耦趋势出现后，逐步提高重建/交换权重，并保留解耦约束；同时要求补全优于静态原型且 task 泛化不退化。
4. 在相同配置下再比较 shared/branch 1/1 层与 2/2 层。验证集判定，Test 只作最终报告。

仅同类聚合不能证明没有交叉信息泄漏；后续应同时测两分支的 task 和 subject 信息，配合同属性交换，并以最终分类验证收益。
