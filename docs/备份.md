我备份的是 LaBraM-origin_preexp12 在完成 preexp12 主线补通道改造后的状态：为了让 TUEV-13 输入
  能够在模型内部补成 TUEV-23，我已经改了参数入口、prototype 加载、模型里的 prototype buffer、
  forward_features 补通道逻辑、TUEV 的 channel_subset 数据裁剪、best_metric 选择 best epoch，以
  及 17O 运行脚本里的 best_metric / freeze_cnn 开关。之后继续改的是 LaBraM-origin_preexp12，
  LaBraM-origin_preexp12 copy 保留的是这一步完成后的备份。


主要改的是这几个文件：

  1. run_class_finetuning.py

  加了 channel_subset / completion_scope / pooling_scope / channel_prototype_path /
  freeze_cnn / best_metric，负责读取 prototype、配置模型、选择 best epoch。

  2. modeling_finetune.py

  加了 prototype buffer、completion_scope 状态，以及 forward_features() 里的补通道逻辑。

  3. utils.py

  让 TUEVLoader / prepare_TUEV_dataset 支持 channel_names，从而真正把 TUEV-23 裁成 TUEV-13。

  4. Channels_definition.py

  统一维护 TUEV-13、TUEV-23、SEEDV-23、SEEDV-62 等通道定义。

  5. scripts/tuev/17O.finetune_tuev_labrambase_freeze_cnn_train_transformer_head_eval.sh

  加了 best_metric、freeze_cnn 开关等运行参数。

  docs/prototypes/01_generate_tuev_cnn_patch_prototypes.py
  docs/prototypes/00_check_pth.py

  用于生成和检查 TUEV-23 prototype。
